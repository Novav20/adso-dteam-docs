# UC-INV-005: Register Physical Asset Master (Catalog)

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-INV-005 |
| **Name** | Register Physical Asset Master (Catalog) |
| **Primary Actor** | Reliability Engineer |
| **Secondary Actors** | N/A |
| **Description** | Allows the formal registration of a new physical asset (Equipment Unit, Level 6) in the master catalog, establishing its initial taxonomic hierarchy according to ISO 14224, defining its technical boundaries, functional location, and operational criticality to support failure analysis and RIME prioritization. |
| **Preconditions** | <ul><li>The Engineer is authenticated in the system with the "Reliability Engineer" role [[TR-006]].</li><li>The master plant taxonomy (Functional Locations) is previously configured in the system.</li><li>The standard Equipment Classes are defined in the reference dictionary.</li></ul> |
| **Main Flow** | 1. The Engineer accesses the Asset Catalog module and selects "Register New Equipment".<br>2. The System displays the registration form requesting technical attributes and chronological milestones.<br>3. The Engineer enters the identification data (Industrial Tag, Serial Number), design and operation attributes (Equipment Class, Manufacturer, Model, Normal Operating Mode, Initial Criticality, Safety Critical Equipment - SCE indicator) and lifecycle dates (Purchase, Installation, Start of Operation).<br>4. The Engineer selects the Functional Location from the hierarchical tree to which the asset will be linked.<br>5. The Engineer confirms the action to save the record.<br>6. The System validates that all critical attributes declared by the ISO 14224 standard are filled out.<br>7. The System validates that the industrial tag and serial number of the equipment are globally unique in the master catalog.<br>8. The System validates the logical coherence of the entered dates (e.g. the start of operation date must be equal to or later than the purchase date).<br>9. The System:<br>   - Atomically persists the new asset data sheet in the database in initial lifecycle status.<br>   - Generates an entry in the immutable audit trail [[TR-001]] via an append-only record with its corresponding chained cryptographic integrity hash (SHA-256), capturing: user, timestamp, Equipment Tag, class, criticality and associated functional location.<br>10. The System displays a success confirmation message and redirects to the detailed view of the new technical data sheet. |
| **Alternate Flows** | **AF-001: Incomplete Mandatory Fields (Redundant Coding)**<br>In step 6, if the Engineer omitted any critical attribute (e.g. Equipment Class or Criticality):<br>   1. The System interrupts the saving transaction.<br>   2. The System highlights the missing fields applying redundant Shape + Color coding (warning symbol and contrast indicator) according to WCAG 2.1 AA and displays a notification: "ISO 14224 Inconsistency: Mandatory technical data is missing to formalize the asset registration."<br>   3. The flow returns to step 3 for correction.<br><br>**AF-002: Identifier Conflict (Duplicate Tag)**<br>In step 7, if the identifier or serial number already exists in the database:<br>   1. The System blocks the persistence to protect the catalog's uniqueness.<br>   2. The System issues an integrity warning: "The entered Identifier/Tag is already assigned to an existing asset. Review the inventory or enter a valid identifier."<br>   3. The flow returns to step 3.<br><br>**AF-003: Chronological Inconsistency of Dates**<br>In step 8, if a temporal paradox is detected (e.g. operation prior to acquisition):<br>   1. The System interrupts the saving.<br>   2. The System alerts about the logical error: "Chronological inconsistency: The start of operation date cannot be prior to the asset's purchase date."<br>   3. The flow returns to step 3 so the Engineer can adjust the equipment's schedule. |
| **Postconditions** | <ul><li>The new physical asset (Equipment Unit) is formalized and uniquely available in the master catalog with its initial criticality for the RIME engine.</li><li>The plant's hierarchical structure is updated reflecting the equipment in its corresponding functional location.</li><li>The creation transaction is protected under the immutable audit trail.</li></ul> |
| **Associated Requirements** | FR-116, FR-117, FR-118, FR-119, FR-120, NFR-121, NFR-122, [[TR-001]], [[TR-008]] |
