# UC-INV-027: Structure Taxonomy of Functional Locations

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-INV-027 |
| **Name** | Structure Taxonomy of Functional Locations |
| **Primary Actor** | Reliability Engineer |
| **Secondary Actors** | N/A |
| **Description** | Allows defining and modifying the master hierarchical structure of the plant according to ISO 14224 (Levels 1 to 5: Industry, Business, Installation, Plant, Section). This taxonomy provides the logical and geographical context where physical assets (Equipment Units) operate, accumulating operational costs and maintaining structural consistency without cycles or orphan nodes. |
| **Preconditions** | <ul><li>The Engineer is authenticated in the system with the "Reliability Engineer" role [[TR-006]].</li><li>The master configuration of ISO 14224 taxonomic levels is defined.</li></ul> |
| **Main Flow** | 1. The Engineer accesses the Taxonomy module and selects the "Add Functional Location" option.<br>2. The System displays the registration form and dynamically adjusts the required fields according to the selected ISO Hierarchical Level (Levels 1 to 5).<br>3. The Engineer enters the Technical Identifier (Tag), Name, Operational Criticality, Geographical Location / Environmental Exposure and the engineering blueprint reference (P&ID). Optionally, selects the parent node in the hierarchy.<br>4. The System executes the domain taxonomic validations [[TR-008]]:<br>   - Validates that the Tag is globally unique in the system.<br>   - Validates that the hierarchical level of the new node is strictly coherent with its parent node (e.g., a Level 4 must be a child of a Level 3).<br>5. The Engineer confirms the node creation.<br>6. The System:<br>   - Atomically persists the new node in the database's taxonomic catalog.<br>   - Records the operation in the immutable audit trail [[TR-001]] via an append-only record with its corresponding chained cryptographic integrity hash (SHA-256).<br>7. The System updates the taxonomic tree view and confirms the success of the operation. |
| **Alternate Flows** | **AF-001: Uniqueness Conflict (Duplicate Tag)**<br>In step 4, if the System detects that the Tag is already in use:<br>   1. The System interrupts the transaction.<br>   2. The System highlights the conflicting field applying redundant Shape + Color coding (warning symbol and contrast indicator) according to WCAG 2.1 AA and alerts: "The entered location Tag already exists. Identifiers must be unique across the entire taxonomy."<br>   3. The flow returns to step 3.<br><br>**AF-002: Tree Reorganization (Cycle Prevention)**<br>If the Engineer decides to move an existing functional location to a new parent node:<br>   1. The Engineer selects the location and defines its new destination node (Re-parenting).<br>   2. The System invokes the structural integrity domain validation.<br>   3. If the System detects that the destination node is a direct or indirect descendant of the node being moved, it blocks the action immediately.<br>   4. The System issues a critical alert: "Integrity violation: The operation would generate an infinite cycle in the hierarchy."<br>   5. If the validation is successful, the System applies the movement atomically and records the structural change in the immutable audit [[TR-001]].<br><br>**AF-003: Attempt to Delete Occupied Node**<br>If the Engineer attempts to delete an existing functional location:<br>   1. The System validates the node's dependencies.<br>   2. If the location has child locations or possesses a physical asset (Equipment Unit) currently installed, the System rejects the deletion.<br>   3. The System notifies: "Action denied: The functional location contains installed assets or hierarchical dependencies. Relocate the elements before proceeding." |
| **Postconditions** | <ul><li>The taxonomic tree is updated and mathematically consistent, without orphan nodes or closed cycles.</li><li>The new functional locations are enabled to receive physical asset installation (Asset Swap).</li><li>The structural evolution of the plant is permanently recorded for audits.</li></ul> |
| **Associated Requirements** | FR-160, FR-161, FR-162, FR-163, FR-164, FR-165, NFR-166, NFR-167, NFR-168, NFR-169, [[TR-001]], [[TR-006]], [[TR-008]] |
