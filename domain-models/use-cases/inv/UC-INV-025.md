# UC-INV-025: Register Rotable Asset Swap (Asset Swap)

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-INV-025 |
| **Name** | Register Rotable Asset Swap (Asset Swap) |
| **Primary Actor** | Reliability Engineer |
| **Secondary Actors** | N/A |
| **Description** | Executes the functional replacement of a physical asset (Equipment Unit, Level 6) without altering the master Functional Location. Specifically designed for rotable spares (e.g., Motors, Pumps), it allows removing a failed asset by its Serial Number and immediately placing an identical replacement from inventory, ensuring that the historical reliability data (MTBF) tracks the specific machine while the Functional Location remains active. |
| **Preconditions** | <ul><li>The Engineer is authenticated in the system [[TR-006]].</li><li>The Functional Location is active and currently has a physically linked asset.</li><li>The replacement asset (Rotable Spare) exists in the master inventory and is in "Available" status.</li></ul> |
| **Main Flow** | 1. The Engineer accesses the detail view of a Functional Location and selects the operation "Asset Swap".<br>2. The System displays the swap form showing the currently installed equipment unit (Asset A) with its Tag and Serial Number.<br>3. The Engineer selects the destination status for Asset A (e.g. "In Repair" or "In Warehouse") and specifies the physical holding warehouse.<br>4. The Engineer selects the replacement equipment (Asset B) from the inventory catalog and optionally enters the identifier of the associated Work Order.<br>5. The Engineer confirms the swap operation.<br>6. The System executes the following taxonomic validations in real time [[TR-008]]:<br>   - Verifies that Asset B belongs to the same Equipment Class required by the Functional Location.<br>   - Validates that Asset B is in "Stock/Available" status and has no active links with other functional locations.<br>7. The System invokes the domain rules to:<br>   - Unlink Asset A from the functional location and update its status to the selected destination.<br>   - Link Asset B to the functional location, update its status to "Operational" and stamp the current date as the start of its operational service.<br>8. The System records the timeline in the domain tracking table (`asset_installations`), closing the `removed_at` timestamp for Asset A and inserting a new row for Asset B with the current `installed_at` timestamp, then persists all changes via an atomic single-commit database transaction.<br>9. The System records the transaction in the immutable audit trail [[TR-001]] via an append-only log with its chained cryptographic hash (SHA-256), capturing: Functional location tag, Serial Number of the removed asset (Asset A), Serial Number of the installed asset (Asset B), user, date and justifying Work Order.<br>10. The System displays a success confirmation and updates the hierarchical view reflecting the new configuration. |
| **Alternate Flows** | **AF-001: Replacement Asset Unavailable or Incompatible**<br>In step 6, if the system detects that Asset B does not belong to the same Equipment Class or its status changed to "Damaged":<br>   1. The System blocks the atomic transaction to protect the integrity of the physical catalog.<br>   2. The System alerts the user: "Taxonomic incompatibility: The selected replacement equipment does not belong to the required Equipment Class or is not available in the warehouse."<br>   3. The flow returns to step 4.<br><br>**AF-002: Incomplete Dismantling Destination (Redundant Coding)**<br>In step 5, if the Engineer omits specifying the destination status or the holding warehouse for the removed asset:<br>   1. The System interrupts the operation indicating that the asset cannot remain in a state of logical orphanhood.<br>   2. The System highlights the missing mandatory fields via redundant Shape + Color coding (warning symbol and contrast indicator) according to WCAG 2.1 AA.<br>   3. The flow returns to step 3. |
| **Postconditions** | <ul><li>The original asset (Asset A) is unlinked from the functional location and passes to the control of the warehouse or workshop under its individual Serial Number.</li><li>The new asset (Asset B) assumes the operational position, recording the current start of service date.</li><li>The swap transaction is consolidated in both the immutable audit trail and the dedicated `asset_installations` tracking table for fast MTBF calculations.</li></ul> |
| **Associated Requirements** | FR-591, FR-592, FR-593, FR-594, FR-595, NFR-596, NFR-597, [[TR-001]], [[TR-008]] |
