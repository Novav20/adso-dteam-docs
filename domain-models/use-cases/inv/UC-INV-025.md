# UC-INV-025: Register Rotable Asset Swap (Asset Swap)

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-INV-025 |
| **Name** | Register Rotable Asset Swap (Asset Swap) |
| **Primary Actor** | Maintenance Technician |
| **Secondary Actors** | Maintenance Supervisor, Warehouse Manager, Reliability Engineer |
| **Description** | Executes the physical and functional replacement of a serialized equipment unit (Equipment Unit, Level 6) mounted at an active operational position (Functional Location, Level 5) without altering the master Functional Location tag or reliability history. Designed for rotable spares (e.g., centrifugal pumps, electric motors), it unlinks the dismounted equipment unit, links an identical replacement unit from warehouse inventory, updates warehouse ledger movements, and records an immutable cryptographic audit record, preserving historical MTBF calculations on both the functional location and physical machine. |
| **Preconditions** | <ul><li>The Actor is authenticated in the system with role `Maintenance Technician`, `Maintenance Supervisor`, or `Warehouse Manager` ([TR-006](../../../requirements/common/TR-006.md)).</li><li>The Actor accesses the contextual modal dialog ([SCR-INV-025](../../../ui-ux/screens/inv/SCR-INV-025.md)) from an active Work Order ([SCR-MTTO-002](../../../ui-ux/screens/mtto/SCR-MTTO-002.md) via "Rotate Dismounted Equipment") or from the Functional Location Detail view ([SCR-INV-005](../../../ui-ux/screens/inv/SCR-INV-005.md) via "Physical Replacement").</li><li>The target Functional Location is active, governed by an approved Work Permit, and currently has a physically mounted equipment unit.</li><li>When executed within a field Work Order context, mechanical and electrical isolation is verified (active LOTO locks confirmed and telemetry signals indicate zero residual energy per [ASR-002](../../../architecture/asr/DT-ARQ-ASR-001.md)).</li><li>A compatible replacement equipment unit exists in warehouse inventory in `IN_STORAGE` lifecycle status and `OPERATIONAL` maintenance status ([FR-593](../../../requirements/user-stories/inv/INV-025.md#functional-requirements-fr)).</li></ul> |
| **Main Flow** | 1. The Technician invokes the "Asset Swap" operation from the caller screen.<br>2. The System displays the asset swap form populated with the target Functional Location tag and the details of the currently mounted equipment unit (Serial Number, Manufacturer, Model, Operating Hours, Installation Date).<br>3. The Technician selects the post-dismount destination status (`IN_REPAIR` for technical workshop or `IN_STORAGE` for warehouse spare pool) and specifies the receiving warehouse or workshop identifier.<br>4. The Technician selects the replacement equipment unit from the rotable catalog or scans its physical barcode/NFC tag using the mobile device reader.<br>5. The System executes taxonomic compatibility verification in real time [TR-008](../../../requirements/common/TR-008.md):<br>   - Verifies that the replacement equipment unit shares the identical Equipment Class required by the Functional Location.<br>   - Verifies that the replacement equipment unit is in warehouse storage (`IN_STORAGE`), operational maintenance status (`OPERATIONAL`), and is not currently mounted at another operational position.<br>6. The Technician enters or verifies the associated Work Order identifier justifying the operational intervention.<br>7. The System previews the cryptographic integrity hash chaining payload (SHA-256) binding the functional location, dismounted serial, replacement serial, destination warehouse, user, and timestamp [TR-001](../../../requirements/common/TR-001.md).<br>8. The Technician confirms the asset swap operation.<br>9. The System executes the equipment rotation: unlinks the currently mounted equipment unit from the operational location, transitions its lifecycle status to warehouse storage (setting its maintenance condition to `UNDER_MAINTENANCE` or `OPERATIONAL` and operational state to `DOWN` or `STANDBY`), and links the replacement equipment unit to the functional location in `INSTALLED` lifecycle status and `UP` operational status.<br>10. The System records the operational changes within a single atomic transactional boundary ([NFR-596](../../../requirements/user-stories/inv/INV-025.md#non-functional-requirements-nfr)):<br>   - Closes the active installation timeline record for the dismounted equipment unit and opens a new installation record for the replacement unit to preserve continuous MTBF reliability tracking.<br>   - Posts the warehouse inventory ledger movements: records a stock receipt movement for the dismounted unit entering the destination warehouse/workshop, and a stock issue movement for the replacement unit exiting warehouse stock.<br>   - Records the structural audit transaction capturing the immutable cryptographic hash, previous state, new state, user ID, and justifying Work Order ([FR-595](../../../requirements/user-stories/inv/INV-025.md#functional-requirements-fr)).<br>11. The System displays a success confirmation, closes the contextual modal dialog, and returns the Technician to the caller screen ([SCR-MTTO-002](../../../ui-ux/screens/mtto/SCR-MTTO-002.md) or [SCR-INV-005](../../../ui-ux/screens/inv/SCR-INV-005.md)) with the updated mounted equipment serial number reflected in the active session. |
| **Alternate Flows** | **AF-001: Replacement Equipment Incompatible or Unavailable**<br>In step 5, if the System detects that the selected replacement equipment unit belongs to a different Equipment Class, is flagged as decommissioned or under repair, or is already linked to another operational position:<br>   1. The System blocks the substitution transaction to protect taxonomic and structural catalog integrity.<br>   2. The System alerts the user: *"Taxonomic incompatibility: The selected replacement unit does not match the required Equipment Class or is unavailable in warehouse inventory."*<br>   3. The flow returns to step 4.<br><br>**AF-002: Incomplete Dismantling Destination (Redundant Coding)**<br>In step 8, if the Technician attempts to confirm the swap without selecting the destination status or the receiving warehouse for the dismounted equipment unit:<br>   1. The System interrupts the operation, enforcing the anti-orphanhood invariant.<br>   2. The System highlights the missing mandatory fields via redundant Shape + Color coding (warning symbol and amber contrast indicator) per WCAG 2.1 AA.<br>   3. The flow returns to step 3.<br><br>**AF-003: Safety Interlock Violation / Unverified Energy Isolation**<br>In step 1 or step 8, if the swap is triggered within a Work Order context and plant telemetry indicates active electrical current/fluid pressure, or if required LOTO isolation points are not formally attested and locked:<br>   1. The System activates the safety interlock, hard-disabling the execution action.<br>   2. The System displays an emergency safety banner: *"Operational Safety Interlock: Equipment cannot be mechanically uncoupled while energy isolation remains unverified. Confirm zero energy state before proceeding."*<br>   3. The flow is aborted.<br><br>**AF-004: Offline Network Partition & Command Outbox Enqueuing**<br>In step 1, if the mobile device is operating in a disconnected plant zone without network connectivity ([TR-007](../../../requirements/common/TR-007.md)):<br>   1. The System displays the offline indicator ("SIN CONEXIÓN · ENCOLADO LOCAL").<br>   2. The Technician executes steps 1 through 8 normally using local encrypted storage ([TR-002](../../../requirements/common/TR-002.md)).<br>   3. In step 10, the System generates client-side unique identifiers ([ADR-005](../../../architecture/adr/ADR-005.md)), persists the transaction locally, and enqueues the command payload into the local offline synchronization queue ([ADR-006](../../../architecture/adr/ADR-006.md)).<br>   4. The modal presents a local confirmation notice and returns to the caller screen with an incremented pending synchronization counter.<br>   5. Upon network recovery, the background synchronization service automatically dispatches the enqueued transaction to the central application service using the idempotency key to guarantee single-commit execution. |
| **Postconditions** | <ul><li>The dismounted equipment unit is unlinked from the functional location, assigned to the receiving warehouse/workshop, and transitions its lifecycle status to `IN_STORAGE`.</li><li>The replacement equipment unit assumes the operational position, clears warehouse stock assignment, and transitions its operational status to `UP` and lifecycle status to `INSTALLED`.</li><li>The equipment installation timeline is updated atomically, closing the prior service interval and opening the new active period for accurate MTBF calculations.</li><li>The warehouse inventory ledger records the corresponding issue and receipt movements with exact serial numbers and movement reasons.</li><li>An immutable audit log entry is recorded with the chained SHA-256 cryptographic hash.</li><li>The contextual modal dialog closes and returns control to the parent caller screen with refreshed serial references.</li></ul> |
