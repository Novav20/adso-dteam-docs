# UC-INV-006: Process Inventory Transaction (Kardex)

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-INV-006 |
| **Name** | Process Inventory Transaction (Kardex) |
| **Primary Actor** | Inventory Manager |
| **Secondary Actors** | N/A |
| **Description** | Executes and records all physical and logical movements of materials, spare parts, and tools in the warehouse (In, Out, Transfer, Adjustment, Reservation), ensuring atomic consistency of the available stock levels and financial cost traceability for Work Orders. |
| **Preconditions** | <ul><li>The Inventory Manager is authenticated in the system [[TR-006]].</li><li>The spare part or material to be transacted is registered in the master catalog.</li><li>If the transaction is an output, the target Work Order must exist and be in a valid status (e.g. `PLANNING` or `IN_PROGRESS`).</li></ul> |
| **Main Flow** | 1. The Inventory Manager accesses the "Inventory Operations" module and selects "New Transaction".<br>2. The System displays the transaction form.<br>3. The Manager selects the Transaction Type: "Output for Work Order" (OUT).<br>4. The Manager enters the reference of the target Work Order and the ID (SKU) of the item to be dispatched (e.g. "Bearing 6204-2Z").<br>5. The System validates the existence of the Work Order and retrieves the current stock availability of the selected item in the source warehouse.<br>6. The Manager specifies the quantity to dispatch (e.g. 2 units) and the source location (e.g. "Warehouse A, Bin 14").<br>7. The System validates that the requested quantity is less than or equal to the available stock in the specified location.<br>8. The Manager confirms the transaction.<br>9. The System executes a transactional block in the database (ACID):<br>   - Deducts the dispatched quantity from the physical and available stock of the item in the specified warehouse.<br>   - Calculates the transaction cost based on the active inventory valuation method (e.g. Average Cost).<br>   - Generates the transaction record in the Kardex with the transaction ID, type, item, quantity, cost, user, timestamp, and reference to the Work Order.<br>   - Updates the total material cost of the target Work Order.<br>10. The System confirms transactional persistence in the Kardex ledger. If the operation is a manual Stock Adjustment (discrepancy / inventory write-off, AF-003), the event is also recorded in the immutable audit trail [[TR-001]].<br>11. The System displays a success confirmation and the unique transaction folio number. |
| **Alternate Flows** | **AF-001: Insufficient Stock (Validation Error)**<br>In step 7, if the requested quantity exceeds the available stock in the location:<br>   1. The System blocks the transaction.<br>   2. The System highlights the quantity field with an error indicator and displays the message: "Insufficient stock. The requested quantity exceeds the available stock (Current: X units)."<br>   3. The flow returns to step 6 for the Manager to adjust the quantity.<br><br>**AF-002: Reorder Point Trigger (Automated Event)**<br>In step 9, after the stock deduction, if the new physical stock of the item is equal to or less than its configured Reorder Point:<br>   1. The System automatically generates a "Purchase Requisition" draft for the item.<br>   2. The System sends a notification to the Purchasing Department: "Reorder point reached for Item [SKU]. Suggested replenishment: [Economic Order Quantity]."<br>   3. The main flow continues normally.<br><br>**AF-003: Stock Adjustment (Physical Count)**<br>In step 3, if the Manager selects Transaction Type: "Physical Adjustment" (ADJUST):<br>   1. The Manager enters the item, the actual physical quantity counted, and a justification code (e.g. "Shrinkage", "Counting Error").<br>   2. The System calculates the difference between the physical count and the logical stock.<br>   3. The System adjusts the logical stock to match the physical count and records a financial loss/gain entry in the Kardex.<br>   4. The System records the manual discrepancy and justification in the immutable audit trail [[TR-001]].<br>   5. The flow continues to step 11. |
| **Postconditions** | <ul><li>The inventory movement is immutably recorded in the transactional Kardex ledger (`inv.inventory_transactions`).</li><li>The stock levels and available stock of the spare part are updated atomically in the database.</li><li>The cost of the associated work order is updated with the real value of the dispatched or returned materials.</li><li>Manual stock adjustments and inventory write-offs are cryptographically audited under [[TR-001]].</li></ul> |
| **Associated Requirements** | FR-125, FR-126, FR-127, FR-128, FR-129, FR-130, FR-131, [[TR-001]] |
