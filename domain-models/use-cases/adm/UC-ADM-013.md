| **Nombre**               | Gestionar Roles y Permisos                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

| **Descripción**          | Permite al Administrador del Sistema crear, modificar y estructurar los roles de usuario y sus permisos de acceso granulares en la plataforma, aplicando restricciones estrictas de Segregación de Funciones (SoD) para evitar conflictos de interés o la omisión involuntaria de controles de seguridad según las normas ISO 55001 e ISO 27001.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Precondiciones**       | <ul><li>El Administrador está autenticado en la consola web con credenciales válidas y rol autorizado para la gestión de accesos [[TR-006]].</li><li>La matriz maestra de módulos del sistema (MTTO, INV, VIS, ADM) está disponible y parametrizada.</li></ul>                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Flujo Principal**      | 1. El Administrador accede al menú de Configuración de Seguridad y selecciona "Gestionar Roles y Permisos".<br>2. El Administrador selecciona la opción "Crear Nuevo Rol" e ingresa los datos básicos obligatorios: nombre del rol (ej. "Planificador de Mantenimiento") y descripción de responsabilidades.<br>3. El Sistema presenta la matriz de permisos granular dividida por módulos funcionales.<br>4. El Administrador configura las acciones autorizadas para el rol, marcando los privilegios de forma específica: Crear, Leer, Editar, Eliminar, Aprobar, Auditar y Ejecutar.<br>5. Al procesar la selección, el Sistema evalúa las reglas de negocio para garantizar la Segregación de Funciones (SoD):<br>&nbsp;&nbsp;&nbsp;- Verifica que los permisos asignados no violen políticas críticas de control de riesgos (ej. impedir que un mismo rol posea privilegios de creación y aprobación final sobre el mismo proceso).<br>6. El Administrador confirma la creación del rol.<br>7. El Sistema:<br>&nbsp;&nbsp;&nbsp;- Persiste de forma atómica la estructura del nuevo rol y sus permisos asociados en el catálogo de seguridad.<br>&nbsp;&nbsp;&nbsp;- Registra la operación en el rastro de auditoría inmutable [[TR-001]], generando un registro de solo inserción con su hash criptográfico (SHA-256) encadenado.<br>&nbsp;&nbsp;&nbsp;- Despacha de forma asíncrona una notificación de actualización para propagar los nuevos permisos a todas las sesiones activas en un tiempo máximo de 2 segundos.<br>8. El Sistema muestra una confirmación en pantalla: "Rol creado exitosamente." |
| **Flujos Alternativos**  | **AF-001: Bloqueo Estricto por Segregación de Funciones (SoD)**<br>En el paso 5, si el Sistema detecta que la combinación de permisos genera un riesgo operativo directo (ej. permitir que el rol "Técnico" pueda firmar de forma autónoma su propio cierre LOTO):<br>   1. El Sistema **bloquea de forma estricta** la operación de guardado.<br>   2. El Sistema destaca en rojo los permisos en conflicto y despliega un aviso de error normativo: "Bloqueo de Seguridad (ISO 27001 A.5.3): La combinación de permisos seleccionada viola la política de Segregación de Funciones. Debe desmarcar una de las acciones en conflicto para continuar."<br>   3. El Administrador desmarca la acción incompatible y el flujo regresa al paso 5.<br><br>**AF-002: Intento de Modificación de Rol Raíz (Super Admin)**<br>En el menú de gestión, si el Administrador intenta editar o eliminar el rol maestro de administración del sistema:<br>   1. El Sistema deniega la operación, bloquea los controles de modificación en la interfaz y muestra un mensaje de error crítico: "Acción Denegada: La integridad del rol raíz del sistema es inmutable y no puede ser alterada ni eliminada."<br>   2. El flujo finaliza regresando a la lista de roles.                                                                                                                                                                                                                                                                                                                                                           |
| **Postcondiciones**      | <ul><li>El nuevo rol de usuario queda consolidado y disponible de forma inmediata para su asignación.</li><li>La matriz de permisos se propaga a la capa de autorización del sistema para evaluar las peticiones de acceso entrantes con latencia mínima.</li><li>La transacción de alteración de permisos queda registrada de forma inalterable en la bitácora de auditoría.</li></ul>                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
