# UC-ADM-013: Manage Role-Based Access Control (RBAC) and Security

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-ADM-013 |
| **Name** | Manage Role-Based Access Control (RBAC) and Security |
| **Primary Actor** | System Administrator |
| **Secondary Actors** | N/A |
| **Description** | Provides the core administration interface to create, modify, and define the granular access limits of user roles across the platform. It strictly enforces Segregation of Duties (SoD) to prevent operational conflicts and ensures that all authorization changes are immutably logged for ISO 27001 compliance. |
| **Preconditions** | <ul><li>The Administrator is authenticated in the web console with valid credentials and authorized role for access management [[TR-006]].</li><li>The master matrix of system modules (MTTO, INV, VIS, ADM) is available and parameterized.</li></ul> |
| **Main Flow** | 1. The Administrator accesses the Security Configuration menu and selects "Manage Roles and Permissions".<br>2. The Administrator selects the "Create New Role" option and enters the mandatory basic data: role name (e.g., "Maintenance Planner") and responsibility description.<br>3. The System presents the granular permissions matrix divided by functional modules.<br>4. The Administrator configures the authorized actions for the role, specifically marking the privileges: Create, Read, Edit, Delete, Approve, Audit, and Execute.<br>5. Upon processing the selection, the System evaluates the business rules to guarantee Segregation of Duties (SoD):<br>&nbsp;&nbsp;&nbsp;- Verifies that the assigned permissions do not violate critical risk control policies (e.g., preventing the same role from having creation and final approval privileges over the same process).<br>6. The Administrator confirms the role creation.<br>7. The System:<br>&nbsp;&nbsp;&nbsp;- Atomically persists the structure of the new role and its associated permissions in the security catalog.<br>&nbsp;&nbsp;&nbsp;- Records the operation in the immutable audit trail [[TR-001]], generating an append-only record with its chained cryptographic hash (SHA-256).<br>&nbsp;&nbsp;&nbsp;- Asynchronously dispatches an update notification to propagate the new permissions to all active sessions within a maximum time of 2 seconds.<br>8. The System displays a confirmation on screen: "Role created successfully." |
| **Alternate Flows** | **AF-001: Strict Block due to Segregation of Duties (SoD)**<br>In step 5, if the System detects that the combination of permissions generates a direct operational risk (e.g., allowing the "Technician" role to autonomously sign their own LOTO closure):<br>   1. The System **strictly blocks** the save operation.<br>   2. The System highlights the conflicting permissions in red and displays a regulatory error notice: "Security Block (ISO 27001 A.5.3): The selected combination of permissions violates the Segregation of Duties policy. You must uncheck one of the conflicting actions to continue."<br>   3. The Administrator unchecks the incompatible action and the flow returns to step 5.<br><br>**AF-002: Attempt to Modify Root Role (Super Admin)**<br>In the management menu, if the Administrator attempts to edit or delete the system's master administration role:<br>   1. The System denies the operation, blocks the modification controls in the interface, and displays a critical error message: "Action Denied: The integrity of the root system role is immutable and cannot be altered or deleted."<br>   2. The flow ends, returning to the role list. |
| **Postconditions** | <ul><li>The new user role is consolidated and immediately available for assignment.</li><li>The permissions matrix is propagated to the system's authorization layer to evaluate incoming access requests with minimal latency.</li><li>The permission alteration transaction is unalterably recorded in the audit log.</li></ul> |
| **Associated Requirements** | FR-247, FR-248, FR-249, FR-250, FR-251, FR-252, FR-253, FR-254, NFR-255, NFR-256, NFR-257, [[TR-001]], [[TR-006]] |
