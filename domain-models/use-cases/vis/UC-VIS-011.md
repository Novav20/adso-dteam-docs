# UC-VIS-011: Verify Zero Energy Condition (LOTO-TryOut)

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-VIS-011 |
| **Name** | Verify Zero Energy Condition (LOTO-TryOut) |
| **Primary Actor** | Maintenance Technician |
| **Secondary Actors** | Telemetry Service (IoT), HSEQ Inspector (notified on breach) |
| **Description** | Critical security workflow that dictates the final verification step before initiating a physical intervention on an asset. The system validates Lockout/Tagout (LOTO) isolation by crossing manual checks (checklists, physical padlock IDs, Try-Out) with telemetry sensor data in real-time, ensuring a strict "Zero Energy" state to prevent severe accidents. |
| **Preconditions** | <ul><li>The Maintenance Technician is authenticated in the system on an authorized mobile device [[TR-006]].</li><li>The target Work Order is in `PLANNING` or `SCHEDULED` status.</li><li>The asset's isolation points (LOTO) and active telemetry sensors are properly mapped in the digital twin.</li></ul> |
| **Main Flow** | 1. The Technician accesses the Work Order on their mobile terminal and requests to visualize the LOTO route.<br>2. The System renders the asset schematic, highlights the energy flow and identifies the physical cutoff points.<br>3. The System displays the safety header indicating the applicable standard operating procedure (SOP), mandatory personal protective equipment (PPE), an informative notice about other active permits on the asset (SIMOPS awareness) and the sequential isolation checklist.<br>4. The Technician moves to the field, places the physical padlocks/tags on each cutoff point and enters or verifies the applied Padlock Tag IDs in the list.<br>5. The Technician executes the physical absence of tension test (Try-Out test) on the asset and marks the confirmation of the test on the checklist.<br>6. The System requests a synchronous verification from the Telemetry Service to validate the sensor readings at the cutoff points.<br>7. The Telemetry Service confirms the Zero Energy condition. The System enables the control to start the work.<br>8. The Technician confirms the start of the intervention.<br>9. The System:<br>&nbsp;&nbsp;&nbsp;- Updates the Work Order status to execution (`IN_PROGRESS`).<br>&nbsp;&nbsp;&nbsp;- Records the physical padlock identifiers, Zero Energy telemetry readings, and isolation signatures directly in the dedicated Work Order Isolation registry to support fast safety compliance querying.<br>&nbsp;&nbsp;&nbsp;- Records the execution state transition in the immutable audit trail [[TR-001]] via an append-only log, capturing the user, timestamp, and action hash.<br>&nbsp;&nbsp;&nbsp;- Enables the order execution interface for the technician in the field. |
| **Alternate Flows** | **AF-001: Active Energy Detected**<br>In step 6 (or through continuous monitoring prior to start), if telemetry reports energy levels above the safety threshold:<br>   1. The System interrupts the status transition and blocks work enablement.<br>   2. The System issues a critical alert visualizing the anomalous reading: "DANGER: Active energy detected. Intervention blocked."<br>   3. The flow returns to step 4, waiting for the residual energy to dissipate or the physical isolation to be corrected.<br><br>**AF-002: Field Connection Loss (Offline Lease Safety Fallback)**<br>At any time before step 8, if the mobile terminal loses communication with the central server (e.g. in shielded environments or confined spaces):<br>   1. The mobile terminal detects network partition and verifies the presence of an active Cryptographic Offline Lease [[ADR-006]].<br>   2. If the Offline Lease is active and unexpired:<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;a. The System prompts for mandatory local confirmation of physical isolation: the Technician must manually re-verify and confirm the physical Try-Out test (absence of energy) and lock placement.<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;b. The System unlocks the work start control under "Offline Verified Safety Mode" and queues the execution start command in the local offline outbox [[TR-007]].<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;c. Upon reconnecting, the sync worker reconciles the offline safety execution with the central system.<br>   3. If the Offline Lease is expired or absent:<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;a. The System enforces the fail-safe lock, disabling the work start interface.<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;b. The System notifies: "Connection Lost and Offline Safety Lease expired. Re-establish connection or provide authorized Supervisor Cryptographic Override to proceed."<br>   4. The operation remains locked until reconnection renews the lease or the override is validated.<br><br>**AF-003: Re-energization During Execution**<br>After step 9, while the order is in progress:<br>   1. Continuous background monitoring detects an accidental energy flow in the isolated line.<br>   2. The System automatically and immediately forces the suspension of the Work Order.<br>   3. The System issues maximum evacuation alerts on the Technician's terminal and dispatches emergency notifications to the HSEQ supervision consoles. |
| **Postconditions** | <ul><li>The Work Order transitions to execution only under proven guarantee of Zero Energy and physical Try-Out verification.</li><li>Operational safety conditions (sensor readings and padlock identifiers) are durably preserved in the transactional Work Order Isolation registry for immediate OSHA compliance reporting, while the state transitions remain cryptographically audited.</li><li>The system remains in a continuous monitoring state to react to energy contingencies.</li></ul> |
