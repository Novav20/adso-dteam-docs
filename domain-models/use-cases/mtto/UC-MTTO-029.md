# UC-MTTO-029: Define Asset Physical Boundaries (Boundaries)

## Use Case Template

| **Element** | **Detail** |
| :--- | :--- |
| **ID** | UC-MTTO-029 |
| **Name** | Define Asset Physical Boundaries (Boundaries) |
| **Primary Actor** | Reliability Engineer |
| **Secondary Actors** | N/A |
| **Description** | Guarantees taxonomic consistency and strict physical scoping of assets following the principles of ISO 14224. This use case defines the logical and physical boundary (P&ID reference, start/end) of an equipment unit (Level 6), ensuring that its subunits (Level 7) and maintainable items (Level 8) are exclusively framed within said limit, preventing overlapping assignments and generating a solid baseline for failure analysis. |
| **Preconditions** | <ul><li>The Engineer is authenticated in the web system with the "Reliability Engineer" role [[TR-006]].</li><li>The asset (Equipment Unit, Level 6) exists in the master catalog in "DRAFT" status.</li><li>The master components (Subunits and Maintainable Items) that will be associated are available in the master reference tables.</li></ul> |
| **Main Flow** | 1. The Reliability Engineer accesses the technical data sheet of an asset in draft status and selects the option "Configure Physical Boundaries".<br>2. The System displays the configuration form, making the following fields mandatory:<br>   - Reference to the Piping and Instrumentation Diagram (P&ID).<br>   - Physical description of the initial boundary (process start point).<br>   - Physical description of the final boundary (process end point).<br>   - Structuring of Subunits (Level 7) associated with the equipment.<br>   - Selection of one or more logical components (Maintainable Items, Level 8) linked to their respective subunits.<br>3. The Engineer enters the diagram "PID-1045", the initial boundary ("4-inch suction flange"), the final boundary ("3-inch discharge flange"), defines the subunit "Sealing System" and associates the component "Mechanical Seal" to it.<br>4. The System executes an automatic validation of uniqueness and hierarchical integrity [[TR-008]]:<br>   - It verifies at runtime that none of the selected components currently belong to the boundaries of another operational master asset in the catalog.<br>   - It verifies that the parent-child relationships (Equipment $\to$ Subunit $\to$ Item) remain coherently structured.<br>5. The System confirms that the boundaries and selected components are free of collisions and are taxonomically consistent.<br>6. The Engineer confirms saving the configuration.<br>7. The System:<br>   - Atomically persists the physical boundary, P&ID reference and logical component association in the database.<br>   - Records the transaction in the immutable audit [[TR-001]] via an append-only log with its corresponding chained cryptographic integrity hash.<br>8. The System updates the technical status of the asset's data sheet, enabling it for the final validation and commissioning flow. |
| **Alternate Flows** | **AF-001: Assignment Collision (Duplicate Component)**<br>In step 4, if the system validation detects that one of the selected components (e.g., "Mechanical Seal SM-02") is already assigned to the boundaries of another registered equipment unit:<br>   1. The System interrupts the saving process.<br>   2. The System highlights the conflicting component in the interface applying redundant Shape + Color coding (warning icon and contrast) according to WCAG 2.1 AA, and displays an error message: "ISO 14224 consistency error: The selected component already belongs to the physical boundaries of another asset. Unlink the component from the source asset before saving."<br>   3. The flow returns to step 3.<br><br>**AF-002: Connection Loss (Progress Preservation)**<br>During field configuration, if the client experiences an unexpected crash or temporary connection loss:<br>   1. The System locally preserves the progress and the temporary hierarchical structure built in the form.<br>   2. Upon restoring the session or reopening the boundaries form, the System recovers the screen state and allows continuing with the normal flow from step 3.<br><br>**AF-003: Read-Only Boundary Consultation (Mobile in Field)**<br>If a Maintenance Technician is consulting an asset's data sheet in the field from their mobile device:<br>   1. The Technician selects the option "View Technical Boundaries".<br>   2. The System displays the asset's technical information in read-only mode, showing the P&ID reference, process physical descriptions (start/end) and the relationship of subunits and components in a hierarchical dropdown format. |
| **Postconditions** | <ul><li>The draft asset has its physical boundaries, engineering references (P&ID) and logical components (Levels 7 and 8) safely defined in the database.</li><li>The asset is mandatorily enabled for technical validation and subsequent operational activation.</li><li>Structural changes to the hierarchy are recorded in the cryptographic audit trail.</li></ul> |
