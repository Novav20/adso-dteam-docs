# ADR-005: Adoption of PostgreSQL 18 as the Relational Persistence Engine

## Context
The Digital Twin design requires the persistence of two massive and concurrent data streams: the immutable audit log and sensor telemetry. Initially, PostgreSQL 16 was considered. However, the use of UUIDv4 identifiers (completely random) fragments B-Tree index pages in high-volume tables, degrading insertion performance. Additionally, the audit requirement ([[ADR-003]]) demands capturing the previous and new state of each modified row with minimal latency.

## Decision
**PostgreSQL 18** is adopted as the base relational engine for the DTEAM project. 
The architecture will exploit two native features exclusive to this version:
1. **Native generation of `uuidv7()`:** It will be used as the default value for all primary keys. Being chronologically ordered (48 bits of timestamp), insertions are sequentially added to the last leaf of the B-Tree, maximizing disk performance.
2. **The `RETURNING old.*, new.*` clause:** It will be used in the Entity Framework Core `SaveChangesInterceptor` to capture the atomic state before and after a mutation in a single network round-trip.

## Alternatives Considered
* **PostgreSQL 16 or 17 with `uuid-ossp` extension:** Rejected. Forces dependency on extensions for UUID generation and does not solve native index fragmentation unless custom sequencing routines are implemented, which adds technical debt.

## Consequences

### Positive
* Sustained insertion performance in massive tables (telemetry, logs) thanks to time-sequential identifiers.
* Reduction of network latency by eliminating previous `SELECT` statements for mutation auditing.

### Negative
* Forces the use of the latest Docker images (Edge/Latest) of the database engine during development.

### Risks and Technical Debt
* **Extension Compatibility:** We assume the temporary risk that critical extensions like TimescaleDB may experience compatibility delays during the first minor updates of PostgreSQL 18. This will require container image validation before going to production.
