# ADR-001: Hybrid Visualization Strategy (2D First, 3D Evolutionary)

## Context
The EAM Digital Twin requires a spatial representation of the industrial plant to visualize telemetry and apply the ISA-101 safety philosophy and LOTO routes. Implementing a 3D engine requires processed CAD or STEP models, which delays the validation of the functional safety logic and consumes a high level of memory on mobile field devices, affecting the [ASR-001](../asr/DT-ARQ-ASR-001.md#1-offline-first-operation-and-partition-tolerance) performance requirement.

## Decision
A **Hybrid Visualization Strategy** is adopted:
1. **MVP (2D Canvas):** The system will use 2D representations based on scalable SVG vector schematics natively embedded in Razor components. The canvas operates under a 3-tier progressive semantic zoom model (`DT-UI-DS-DOC-001 §2.5`, `SCR-VIS-033`): at Level 1 (L1 - Terminal / Overview) it acts as a *Simplified Plot Plan / Process Overview*, showing the spatial silhouette of battery limits and general layout; at Level 2 (L2 - Zone / Subsystem) it reveals area equipment and pipe manifolds; and at Level 3 (L3 - Equipment / Detail) it reveals asset tags, instrumentation, and contextual faceplates. Ingestion normalizes raw EPC CAD drawings via cartographic abstraction, stripping non-interactive manufacturing micro-geometry (stair treads, bolt circles) to guarantee DOM budgets and eliminate cognitive clutter. This eliminates the need for third-party graphics engines for the initial release, allowing direct DOM manipulation for alerts.
2. **Architectural Abstraction:** Security layers will operate on agnostic spatial metadata.
3. **3D Evolution:** The system will transition to a 3D engine in later phases, consuming the same business logic and metadata without requiring backend rewrites. The linkage will be done via the *Sidecar* pattern and the decoupled `MeshMapping` entity: the domain is unaware of the graphics engine and is linked via geometric identifiers (`svgElementId` in 2D and `meshUuid` in 3D), mapped exclusively to ISO 14224 Level 6 (`EquipmentUnit`).

## Alternatives Considered
* **Use SkiaSharp for 2D:** Rejected. Generates WebView inter-process/canvas serialization overhead in Blazor Hybrid and duplicates vector interaction logic across `Dteam.Web` and `Dteam.Mobile`.
* **Early WebGL or Three.js integration:** Rejected. High probability of memory exhaustion failures in the mobile web viewer when loading complex meshes.

## Consequences

### Positive
* Reduced rendering latency and lower battery consumption on mobile devices.
* Native interaction between Blazor component state and graphic vectors.

### Negative
* 2D maps require manual design and are not automatically generated from plant engineering.

### Risks and Technical Debt
* Forces refactoring of the client visual component when the 3D module is enabled, maintaining compatibility with previously mapped 2D coordinates.
