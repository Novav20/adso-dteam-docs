# ADR-007: Distributed Caching with Redis for Idempotency

## Status
Approved

## Context
The system involves field technicians operating in offline-first mode using a mobile application. When connectivity is restored, the application synchronously transmits a queue of transactional operations (e.g., LOTO status changes, consumption reports). Network unreliability can lead to duplicate transmission of identical payloads if acknowledgments drop. We need a fast, distributed mechanism to enforce strict idempotency across multiple API nodes.

## Decision
We will deploy **Redis** as a distributed, in-memory datastore exclusively for caching idempotency keys. The API gateway (Idempotency Filter) will intercept incoming requests, compute an SHA-256 hash of the payload plus the request UUID, and perform a `SETNX` (Set if Not Exists) operation on Redis with a TTL of 24 hours.

## Consequences
**Positive:**
- Millisecond-latency validation of duplicate requests.
- Ensures identical transactions are processed exactly once.
- Decouples idempotency logic from the primary PostgreSQL database, preventing lock contention.

**Negative:**
- Introduces an additional infrastructural dependency (Redis cluster).
- Requires monitoring and eviction policies to prevent out-of-memory errors on the cache nodes.
