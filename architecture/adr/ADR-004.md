# ADR-004: Unified Frontend Client with .NET MAUI Blazor Hybrid and Blazor Web

## Context
The system requires a robust mobile client for field execution with support for offline operation and an administrative web portal. Maintaining two separate ecosystems imposes a high maintenance burden for a single developer, requiring the management of multiple package managers, duplication of Data Transfer Objects (DTOs), and constant translation of business logic.

## Decision
The frontend technology stack is unified under the .NET ecosystem using a dual-environment topology and a shared Razor class library:

1. **Administrative Web Client:** Blazor Web application.
2. **Field Mobile Client:** .NET MAUI Blazor Hybrid.
3. **Component Library:** High-performance interfaces, ISO 14224 forms, and state logic will be developed only once in a shared project.
4. **Mobile Persistence:** The `sqlite-net-pcl` library integrated with SQLCipher encryption will be used. Entity Framework Core on the mobile client is discarded to avoid cold-start penalties due to reflection usage and conflicts with the native compiler on iOS.

## Alternatives Considered
* **React Web App plus React Native and WatermelonDB:** Rejected. Generates language fragmentation, friction in API client generation, and maintenance overhead due to unstable dependencies.
* **Entity Framework Core over SQLite for mobile persistence:** Rejected. Causes high memory consumption and latency when initializing the database context on low-spec industrial hardware.

## Consequences

### Positive
* Greater development efficiency: domain models, validations, and calculations flow from backend to frontend without code duplication.
* The selected library for SQLite allows for fast transactional inserts without the overhead of a heavy ORM's change tracker, protecting the LOTO safety thread.

### Negative
* Larger final binary size in mobile apps due to the inclusion of the native .NET runtime.
* Synchronization will require manual design of an offline mutation queue table, dispensing with the automatic synchronizers of other tools.

### Risks and Technical Debt
* Interaction performance in large lists may decrease due to rendering within a web viewer instead of using purely native components. Requires strict pagination and component virtualization in the interface.
