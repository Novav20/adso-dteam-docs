# INV-025: Equipment Swap

## Story Description

| Role | Action | Benefit |
|---|---|---|
| Project Engineer | I want to unlink a physical equipment unit from its functional location and install an identical replacement equipment from the inventory. | So that I can preserve the accumulated reliability history in the operational position, record the change of location of the physical machine, and update the state of rotable spare parts in a traceable manner. |

## Acceptance Criteria
| Scenario | Given (Context) | When (Action) | Then (Result) |
|---|---|---|---|
| Successful Equipment Swap execution | Given a failed equipment unit needs replacement at a specific Functional Location. | When the Planner unlinks the current equipment unit and links an identical available equipment unit from the warehouse. | Then the system records the equipment transition, preserves the Functional Location's reliability history, and updates the physical location of both units. |
| Incompatible equipment swap prevention | Given a Planner attempts an equipment swap. | When they try to link an equipment unit of a different Technical Class to the Functional Location. | Then the system blocks the swap, warning about a classification mismatch. |
| Status update post-swap | Given a successful equipment swap has been executed. | When the system finalizes the transaction. | Then the dismantled equipment unit transitions to UNINSTALLED and its technician-selected operational/maintenance destination (IN_STORAGE, IN_REPAIR, or DAMAGED). |
| Audit trail for physical movement | Given an equipment swap is performed. | When the Auditor reviews the equipment's history. | Then they see the exact timestamps and locations for both the unlinked and newly linked equipment units. |
| Successful equipment unit swap | Given a Functional Location has an installed EquipmentUnit (A) (LifecycleStatus = 'INSTALLED', OperationalStatus = 'OPERATIONAL'), a replacement EquipmentUnit (B) is 'UNINSTALLED' and 'IN_STORAGE', and LOTO Zero Energy is verified. | When the Technician executes the atomic swap action linked to an active Work Order. | Then the system transitions unit (A) to LifecycleStatus = 'UNINSTALLED' and OperationalStatus = 'IN_REPAIR' (or 'DAMAGED'), transitions unit (B) to LifecycleStatus = 'INSTALLED' and OperationalStatus = 'OPERATIONAL' at the Functional Location, and records the structural audit transaction. |
| Swap blocked due to non-operational replacement | Given the user selects a replacement equipment unit from inventory. | When said unit is in 'Damaged' or 'Decommissioned' status, or already assigned elsewhere. | Then the system blocks the swap process, issues an incompatibility alert, and does not alter the location's configuration. |
| Historical Traceability log | Given a successful equipment unit swap was completed. | When the technical history of the Functional Location is queried. | Then the system presents a timeline of all physical equipment units installed at that operational position, detailing installation and removal dates. |
| Active LOTO Zero-Energy interlock block on swap | Given an installed EquipmentUnit is linked to an active WorkOrder without verified LOTO Zero Energy. | When the Technician attempts to execute the Equipment Swap. | Then the system blocks the Equipment Swap until LOTO Zero Energy and ConfirmTryOut() are verified. |
| Atomic cross-module swap rollback and offline outbox enqueue | Given an Equipment Swap spans tax, inv, and adm modules (or is queued offline in SyncOutbox). | When a downstream module write fails during swap execution or the client is offline. | Then any cross-module failure rolls back all state changes atomically, or offline execution queues cleanly in SyncOutbox. |

## Functional Requirements (FR)
| ID | Description | ISO 25010 Category | Priority | Source |
|---|---|---|---|---|
| FR-591 | The system shall provide a technical interface to perform the substitution of a physical Level 6 Equipment Unit assigned to a Level 5 (or lower) Functional Location. | Functional Suitability | High | ISO 14224:2016, Section 6 — Taxonomy (Asset Rotation) |
| FR-592 | Upon executing the substitution, the system shall atomically update the uninstalled Equipment Unit's status to "In Repair", "Damaged", or "In Storage" according to user selection. | Functional Suitability | High | ACID Database Transaction Properties (Atomicity) |
| FR-593 | The system shall validate that the selected replacement Equipment Unit is in an "Available" or "In Stock" status within the warehouse, blocking the operation if it is already linked to another location or out of service. | Functional Suitability | High | ISO 14224:2016 — Asset States |
