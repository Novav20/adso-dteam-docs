# VIS-012: 3D Component Hierarchy Configuration

## Story Description

| Role | Action | Benefit |
|---|---|---|
| Project Engineer | I want to define the component hierarchy of an equipment unit (e.g., Pump -> Motor -> Bearing) and associate a 3D model with each level. | So that I can build the exploded view of the Digital Twin and allow technicians to access information on the specific component in the field. |

## Acceptance Criteria
| Scenario | Given (Context) | When (Action) | Then (Result) |
|---|---|---|---|
| Create a sub-component | Given the Engineer is on the page of equipment unit 'Pump P-101' which has no defined components. | When they click 'Add Component', name it 'Electric Motor', and assign code 'ME-01'. | Then 'Electric Motor' must appear as a nested sub-item under 'Pump P-101' in the equipment tree. |
| Associate a 3D model to a component | Given the Engineer is editing the properties of the 'Electric Motor' component. | When they use the 'Upload 3D Model' option and attach a motor.step file. | Then the system must associate that 3D file with the component and display a thumbnail preview. |
| Hierarchical navigation | Given the Technician is viewing the equipment unit 'Pump P-101' in the mobile app. | When they click the exploded view and select the 'Electric Motor'. | Then the app must display the information and the 3D model specific to the 'Electric Motor', not the entire pump. |
| Duplicate component creation attempt | Given the Engineer is adding a component. | When they enter a code that already belongs to another component in the same equipment unit hierarchy. | Then the system prevents the creation and displays a uniqueness error message. |
| Move component in the tree (Re-parenting) | Given a hierarchical tree with multiple defined components. | When the Engineer drags a component (e.g., 'Valve') and drops it under another parent component (e.g., 'Pipe'). | Then the system updates the hierarchical relationship and displays the component in its new nested position. |
